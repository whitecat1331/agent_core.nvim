1. INTRODUCTION                                     *agent_core-intro*

agent_core bundles agent/key profiles with one-key switching, behavior
modes (ask/plan/debug/agent/multi-task), an indexer that generates a
committable project brief (AVANTE.md), and a two-tier context strategy: the
brief is always injected into the system prompt, while deep semantic/structural
context is pulled on demand via MCP tools.

==============================================================================
2. INSTALLATION                                     *agent_core-install*

With lazy.nvim: >

  {
    "whitecat1331/agent_core.nvim",
    config = function()
      require("agent_core").setup()
    end,
  }

3. COMMANDS                                         *agent_core-commands*

                                                *:AgentSwitch*
:AgentSwitch [name]
                Pick an agent/key profile and apply it, or switch directly to
                `name` when given. Default keymap: <leader>aP

                                                *:AgentModel*
:AgentModel     Pick the active chat model from the pooled registry (every
                enabled primary/classifier model across all providers and keys).
                Picking a model also switches to that provider's profile and
                records the concrete model as the active-model override
                (setup.json). The good/cheap/fast policy pre-guesses this
                override during |:AgentSetup|; use :AgentModel to re-pick.

                                                *:AgentModelClear*
:AgentModelClear
                Reset the active model to the active profile's default model
                (clears the setup.json active-model override).

                                                *:AgentMode*
:AgentMode      Pick a behavior mode (ask/plan/debug/agent/multi-task) and
                apply it. Default keymap: <leader>am

                                                *:AgentIndex*
:AgentIndex     Regenerate the project brief (AVANTE.md) for the current repo.
                Default keymap: <leader>aI

                                                *:AgentProfile*
:AgentProfile   Show the active agent profile (read-only).
                Default keymap: <leader>ap

                                                *:AgentRecommend*
:AgentRecommend [prompt]
                Recommend a mode for a prompt. With no argument, uses the
                current visual selection, then falls back to an input prompt.

                                                *:AgentRecommendToggle*
:AgentRecommendToggle
                Enable/disable automatic mode recommendation.

                                                *:AgentAutoSwitch*
:AgentAutoSwitch [prompt]
                Recommend an agent profile for a prompt. With no argument, uses
                the current visual selection, then falls back to an input
                prompt. Default keymap: <leader>ao

                                                *:AgentAutoSwitchToggle*
:AgentAutoSwitchToggle
                Enable/disable automatic agent routing.

                                                *:AgentWorkspaceAdd*
:AgentWorkspaceAdd [path]
                Add a project to the workspace registry. With no argument,
                uses the current directory. Default keymap: <leader>aW

                                                *:AgentWorkspaceRemove*
:AgentWorkspaceRemove
                Remove a project from the workspace registry (picker).

                                                *:AgentWorkspaceScan*
:AgentWorkspaceScan [parent]
                Scan a folder for git repos and register each. With no
                argument, uses config.workspace.scan_parent or the cwd.

                                                *:AgentWorkspaceList*
:AgentWorkspaceList
                List registered workspace projects.
                Default keymap: <leader>aw

                                                *:AgentWorkspaceSwitch*
:AgentWorkspaceSwitch
                Switch to a registered workspace project (picker).
                Default keymap: <leader>aj

                                                *:AgentNotepad*
:AgentNotepad   Open a notepad (picker).
                Default keymap: <leader>an

                                                *:AgentNotepadNew*
:AgentNotepadNew
                Create a new notepad (prompts for a name).

                                                *:AgentNotepadEdit*
:AgentNotepadEdit
                Edit a notepad (picker).

                                                *:AgentNotepadDelete*
:AgentNotepadDelete
                Delete a notepad (picker).

                                                *:AgentBestOfN*
:AgentBestOfN [prompt]
                Compare a prompt across multiple agent profiles and show the
                outputs side-by-side. With no argument, uses the visual
                selection, then falls back to an input prompt.
                Default keymap: <leader>ab

                                                *:AgentPlanBuild*
:AgentPlanBuild [path]
                Switch to agent mode and submit the current/latest plan as the
                prompt ("Build"). With no argument, uses the active plan
                or the most recently modified plan file. Default keymap:
                <leader>aB

                                                *:AgentPlanBuildNew*
:AgentPlanBuildNew [path]
                Like |:AgentPlanBuild|, but opens a fresh agent session
                ("Build in New Agent").

                                                *:AgentPlans*
:AgentPlans
                Open the plan + idea manager: a scratch buffer listing
                unfinished plans (draft + in_progress), completed/abandoned
                plans, and the ideas backlog. <CR> opens a plan or promotes
                an idea, `s` cycles status, `n` adds an idea, `p` promotes an
                idea, `x` deletes an idea, `q` closes.
                Default keymap: <leader>aq

                                                *:AgentPlanIdea*
:AgentPlanIdea [title]
                Add an idea to the project plan backlog
                (.agent_core/plan_ideas.json). With no argument, prompts for
                a title and notes interactively.

                                                *:AgentPlansToggle*
:AgentPlansToggle
                Toggle between the plan + idea manager and the reminder
                badge (or open the badge when neither is shown).
                Default keymap: <leader>aQ

                                                *:AgentCheckpoint*
:AgentCheckpoint [label]
                Snapshot the working tree to a git patch checkpoint. With no
                argument, uses the label "checkpoint". Default keymap:
                <leader>ac

                                                *:AgentRollback*
:AgentRollback [label]
                Restore a checkpoint by reversing its recorded patch
                (git apply -R). With no argument, shows a picker of snapshots.

                                                *:AgentKeep*
:AgentKeep
                Lock in the current turn's file edits (write_to_file /
                str_replace) by advancing the session's discard baseline.
                Default keymap: <leader>aK

                                                *:AgentDiscard*
:AgentDiscard
                Revert every un-kept turn's file edits since the last
                |:AgentKeep| (Cursor-style per-turn Undo All). Deletes files the
                agent created and restores overwritten files to their prior
                bytes. Default keymap: <leader>aX

                                                *:AgentDebugCleanup*
:AgentDebugCleanup
                Remove all recorded debug instrumentation.
                Default keymap: <leader>ad

                                                *:AgentDebugStart*
:AgentDebugStart [config]
                Launch a debug session (real debugger via nvim-dap) by config
                name, or the default launch config for the current filetype.
                Default keymap: <leader>aD

                                                *:AgentDebugContinue*
:AgentDebugContinue
                Resume the current debug session.

                                                *:AgentDebugStepOver*
:AgentDebugStepOver
                Step over the current line.

                                                *:AgentDebugStepInto*
:AgentDebugStepInto
                Step into the current call.

                                                *:AgentDebugStepOut*
:AgentDebugStepOut
                Step out of the current function.

                                                *:AgentDebugStop*
:AgentDebugStop
                Terminate the current debug session.

                                                *:AgentDebugStatus*
:AgentDebugStatus
                Show registered adapters, launch configs, and the latest
                paused state.

                                                *:AgentPredictEdit*
:AgentPredictEdit [instruction]
                Predictive edit: rewrite a window around the caret, grounded in
                surrounding code, LSP diagnostics, and recent edits. Checkpoints
                first, shows a diff, then applies. Default keymap: <leader>ae

                                                *:AgentBugbot*
:AgentBugbot [--autofix] [--base=X]
                Local Bugbot: review the working tree (or a branch vs base) and
                present a severity-ranked findings report. --autofix applies the
                fixes in an isolated worktree and opens a PR. Default keymap:
                <leader>ag

                                                *:AgentMemory*
:AgentMemory    Show persistent agent-written memory in a read-only buffer.
                Default keymap: <leader>aM

                                                *:AgentRun*
:AgentRun [prompt]
                Run one prompt headlessly and print the answer. With no
                argument, prompts for input. Default keymap: <leader>aR

                                                *:AgentPolicy*
:AgentPolicy [alias|knob=value]
                Show or set the model-selection policy. With no argument, opens
                a picker with every alias plus a "(guided setup)" entry that
                walks the three knobs (model policy / trust scope / caution)
                one at a time. Accepts an alias name (e.g. "privacy",
                "cautious") or a "knob=value" pair (e.g.
                "model_policy=cheap"). Default keymap: <leader>ay

                                                *:AgentRegistryList*
:AgentRegistryList
                List every model backend in the registry (roles, trust tier,
                cost, quality tier, provider/model/endpoint).

                                                *:AgentRegistryAdd*
:AgentRegistryAdd name provider model endpoint [trust]
                Add a remote model backend. trust defaults to "private-remote";
                "third-party-cloud" triggers a one-time warning that code leaves
                the machine.

                                                *:AgentKey*
:AgentKey[!] [profile]
                Set a profile's stored API key (prompts for the value, defaulting
                to the current key), or with `!` remove it. With no `profile`,
                a picker opens. Backing for the key-collection step of
                |:AgentSetup|, reachable standalone.

                                                *:AgentProfileEnable*
                                                *:AgentProfileDisable*
:AgentProfileEnable [profile]
:AgentProfileDisable [profile]
                Enable or disable a chat profile by writing a persisted
                setup.json `enabled` override (the same state |:AgentSetup|
                toggles). With no `profile`, a picker opens.

                                                *:AgentEndpointList*
                                                *:AgentEndpointAdd*
                                                *:AgentEndpointRemove*
:AgentEndpointList
:AgentEndpointAdd [url]
:AgentEndpointRemove [url]
                List, add, or remove remote Ollama endpoints. Endpoints are
                persisted to setup.json `ollama_endpoints` (the same state
                |:AgentSetup| writes) and drive Ollama /api/tags discovery, so
                they are also reachable via `:AgentRegistryAdd` +
                registry.ollama_endpoints. With no `url`, Add prompts and
                Remove opens a picker.

                                                *:AgentManager*
:AgentManager   Open a single floating panel that lists and edits profiles
                (enable/disable, set key, switch default), modes (switch
                default), the model policy, and Ollama endpoints (add/remove).
                It delegates to the same functions as the granular commands
                below, so behavior stays in one place. Panel keymaps:

                  <CR>    toggle profile / switch mode / remove endpoint
                  e/d     enable / disable the profile under the caret
                  k       set the API key for the profile under the caret
                  s       switch the default profile
                  m       pick the active model from the pooled registry
                  c       clear the active-model override
                  p       guided policy selector
                  a       add an Ollama endpoint
                  q/Esc   close

                                                *:AgentCheatsheet*
:AgentCheatsheet
                Open a floating, grouped cheat sheet of every agent_core
                command alongside its currently-mapped key. The key column is
                read from live keymap state at render time (not a hardcoded
                table), so |vim.keymap.set()| remaps are reflected on reopen or
                on `r`. `q`/`<Esc>` closes. Default keymap: <leader>a?

                                                *:AgentSetup*
:AgentSetup     First-run setup wizard: detect env/keychain keys and local +
                remote Ollama, show a reviewable form of every chat model,
                collect missing keys, persist the enabled-provider set, then
                walk a default-profile picker, a default-mode picker, and a
                guided policy selector (model policy / trust scope / caution)
                so the install is chat-ready. The AI policy suggestion is
                opt-in (setup.bootstrap). Default keymap: <leader>aS

                                                *:AgentSettingsClear*
:AgentSettingsClear[!]
                Wipe ALL global agent_core state and return to a first-install
                state: purge OS-keychain API keys, delete
                ~/.config/nvim/agent_keys.json, remove the active profile/mode,
                and delete the entire <data>/agent_core/ tree. `!` skips the
                confirmation prompt. Project-scoped files (.agent_core/,
                AVANTE.md, .semnav/, .mcphub/) are NOT touched. Re-run
                |:AgentSetup| afterwards to reconfigure.

                                                *:AgentCatalogUpdate*
:AgentCatalogUpdate
                Refresh the model catalog from config.catalog.url (falling back
                to the bundled snapshot on failure).

                                                *:AgentSkills*
:AgentSkills    List every discovered agent skill (name, scope, description,
                argument hint, path) in a read-only buffer.

                                                *:AgentImport*
:AgentImport    Import rules/skills from another IDE (Cursor or VSCode) into the
                neutral .agent_core/ directories. Single-source and
                non-destructive (existing files are never overwritten).

                                                *:AgentSkill*
:AgentSkill     Run a user-invocable skill (picker), collect its argument, and
                show the invoked body. Default keymap: <leader>at

                                                *:AgentCommands*
:AgentCommands  List every discovered command-palette entry (name, trust, scope,
                description, argv, path) in a read-only buffer.

                                                *:AgentCommand*
:AgentCommand   Pick a command from the palette, collect its required arguments,
                and run it. Default keymap: <leader>aC

                                                *:AgentNextLocation*
:AgentNextLocation
                Predict the next edit location and jump the caret there.
                Default keymap: <leader>aL

                                                *:AgentChat*
:AgentChat [prompt]
                Open the chat workspace — a Cursor-style split with a chat
                list (left), the active chat's message view (right), and a
                multi-line composer (bottom). With a `prompt`, submits it
                immediately. Default keymap: <leader>a<Space>

                                                *:AgentNew*
:AgentNew [prompt]
                Start a fresh chat session: a new empty composer, or submit
                `prompt` in a new session. Default keymap: <leader>aT

                                                *:AgentHistory*
:AgentHistory   List prior agent sessions and resume the selected one into the
                sidebar (picker). Default keymap: <leader>aH

                                                *:AgentSessionBind*
:AgentSessionBind [profile]
                Bind the current session to the active (or a named) profile, so
                resuming the chat restores its model.
                Default keymap: <leader>ah

                                                *:AgentRename*
:AgentRename [name]
                Rename the current session. With no argument, prompts for a
                name. Default keymap: <leader>ar

                                                *:AgentFork*
:AgentFork [name]
                Fork the current session into a new chat and open it. With no
                argument, suffixes the title with "(fork)".
                Default keymap: <leader>aF

                                                *:AgentRewind*
:AgentRewind [index]
                Rewind the current session to a message index (keep messages up
                to and including that index, drop the rest). With no argument,
                opens a picker of messages. Backs up the original to
                <id>.json.rewind-bak. Default keymap: <leader>aU

                                                *:AgentAutomationList*
:AgentAutomationList
                List scheduled automations. Default keymap: <leader>aA

                                                *:AgentAutomationAdd*
:AgentAutomationAdd [prompt]
                Add a scheduled automation (prompts for a repeat interval).

                                                *:AgentAutomationRemove*
:AgentAutomationRemove
                Remove a scheduled automation (picker).

                                                *:AgentAutomationRun*
:AgentAutomationRun
                Run a scheduled automation now (picker).

                                                *:AgentDiffApply*
:AgentDiffApply Apply the accepted hunks of the currently open diff.
                Default keymap: <leader>aa

                                                *:AgentDiffAccept*
:AgentDiffAccept
                Accept the diff hunk under the caret.
                Default keymap: <leader>aY

                                                *:AgentDiffReject*
:AgentDiffReject
                Reject the diff hunk under the caret.
                Default keymap: <leader>aN

                                                *:AgentCoordinatedEdit*
:AgentCoordinatedEdit
                Apply a multi-file coordinated edit, starting from the symbol
                under the caret. Gathers cross-file context, requests a JSON
                edit set, validates paths, checkpoints, applies, and presents a
                combined diff. Default keymap: <leader>aE

get_brief_prompt()                              *agent_core.get_brief_prompt()*
  Returns the project brief text to inject into the system prompt, or "" when
  no brief exists. Bounded by |brief_prompt_max_chars|.

get_mode_prompt()                                *agent_core.get_mode_prompt()*
  Returns the active mode persona text to inject into the system prompt, or ""
  when no mode is set.

get_profile_persona()                    *agent_core.get_profile_persona()*
  Returns the active profile persona text to inject into the system prompt, or
  "" when no profile declares a system_prompt. Injected before the mode
  persona by build_system_prompt.

get_workspace_prompt()                    *agent_core.get_workspace_prompt()*
  Returns the compact multi-root workspace index to inject into the system
  prompt, or "" when no projects are registered. Bounded by
  |workspace.prompt_max_chars|.

get_context_prompt()                    *agent_core.get_context_prompt()*
  Returns the auto-attached editor context block (open buffer window, visual
  selection, LSP diagnostics) to inject into the system prompt, or "" when
  empty. Bounded by |context.max_chars|.

get_rules_prompt()                          *agent_core.get_rules_prompt()*
  Returns the aggregated project + user rules block to inject into the system
  prompt, or "" when no rule files exist. Bounded by |rules.prompt_max_chars|.

get_notepad_prompt()                      *agent_core.get_notepad_prompt()*
  Returns the compact notepad title index to inject into the system prompt, or
  "" when no notes exist. Bounded by |notepad.prompt_max_chars|.

get_memory_prompt()                      *agent_core.get_memory_prompt()*
  Returns the compact agent-memory key index to inject into the system prompt,
  or "" when no memories exist. Bounded by |memory.prompt_max_chars|.

get_skills_prompt()                    *agent_core.get_skills_prompt()*
  Returns the compact skill index (name + description + argument hint) to inject
  into the system prompt, or "" when no skills exist. Bounded by
  |skills.prompt_max_chars|.

get_custom_tools()                        *agent_core.get_custom_tools()*
  Returns every agent_core custom tool (run_agent, web, github, plan, debug,
  checkpoint, bugbot, memory, skills, rules, ask, browser), each wrapped by
  lifecycle hooks. The owned runtime feeds these into the agent loop
  automatically.

  Prompts submitted to the runtime are slash- and mention-aware: `/plan`,
  `/mode`, `/profile`, `/workflow`, and `/agent` dispatch control actions
  (switch mode or profile, run a workflow, or fork a fresh session), while
  `@file`, `@git`, `#buffer`, `@selection`, and `@lsp` expand into context
  before the prompt reaches the agent loop. MCP servers registered in
  ~/.config/mcphub/servers.json are discovered at submit time and their tools
  (ripvec/semnav search) are merged into the agent tool set automatically.

run(prompt, opts, cb)                              *agent_core.run()*
  Runs one prompt headlessly and calls cb({ text=, error=, profile= }). opts may
  set profile / mode / model / on_chunk. The local analog of a headless SDK
  runtime and Automations.

==============================================================================
5. PROJECT BRIEF                                    *agent_core-brief*

:AgentIndex writes AVANTE.md at the git root (or cwd when not a repo). It is
structural only — file paths, language counts, key files, and build/test
commands. It never embeds file contents, so it cannot leak secrets, and it is
safe to commit. The brief auto-refreshes (debounced) after every BufWritePost,
but only if it already exists.

==============================================================================
6. PROFILES                                         *agent_core-profiles*

Profiles are projected from the catalog (lua/agent_core/catalog_snapshot.lua):
an entry that declares a `system_prompt` persona is a routable agent, and
agent_core.profiles (M.defaults) derives its capability tags (cost, latency,
fim, reasoning, vision, quality_tier) from the catalog's numeric fields via
Catalog.cost_tier / Catalog.quality_tier. Catalog-only models (no system_prompt)
do not become profiles. Each profile bundles name, provider, model, api_key_name,
and an optional description / system_prompt. API keys are resolved env-first:
profile.api_key > os.getenv(api_key_name) > agent_keys.json (0600). Never put
real keys in profiles.lua.

Custom profiles: pass `profiles.extra = { ... }` to |agent_core.setup()| or
write <data>/agent_core/profiles.json (an array, or { "profiles": [...] }) to
add agents without replacing the built-ins. `Profiles.all()` returns defaults
plus custom profiles, deduped by name (defaults win). Custom entries declare
`name`, `provider`, `model`, `system_prompt`, `autoswitch`, `keywords`,
`when_to_use`, and optional `endpoint` / `trust` / `roles` / `api_key_name` /
`description` / `fim` / `reasoning` / `vision`; missing capability tags are
defaulted from the provider (e.g. ollama -> local / free / medium). A `endpoint`
on a custom profile reaches the registry (and completion backends), so a private
Ollama box can be its own routable agent. A plain array in `config.profiles` is
still a full replacement (back-compat), but custom profiles are always appended
on top of it. See |agent_core-config| profiles.

==============================================================================
7. MODES                                            *agent_core-modes*

A mode is orthogonal to a profile: profiles pick the model/API key, modes pick
the behavior. Each mode bundles a persona, a tool policy, and an auto-approve
policy. Profiles also carry an optional system_prompt persona, injected before
the mode persona in build_system_prompt. A mode does NOT select a provider or
model — the profile owns provider/model, and any mode-level provider field is
ignored.

  ask        read-only Q&A
  plan       read-only research + write a Markdown plan, then stop
  agent      full tools, auto-approve everything except destructive_tools
  debug      hypothesize -> instrument -> reproduce -> fix -> clean up
  multi-task full tools, parallel fan-out via run_agent

Read-only modes keep read/search tools but disable every mutating tool
(bash, create, edit_file, insert, replace_in_file, str_replace, undo_edit,
write_to_file, write_todos, plus the run_agent / plan / debug / checkpoint
custom tools). A mode can whitelist write tools via allow_tools (plan
allow-lists create_plan, update_plan, and write_todos); M.switch computes
disabled = WRITE_TOOLS - allow_tools. Full modes auto-approve (all tools) minus
destructive_tools. The active mode is persisted and restored on startup.

Custom modes: pass `modes.extra = { ... }` to |agent_core.setup()| or write
<data>/agent_core/modes.json (an array, or { "modes": [...] }) to add modes
without replacing the built-ins. A custom mode is the same shape as a built-in
(name, label, read_only, system_prompt, optional keywords / when_to_use /
allow_tools) and appears in |:AgentMode| and mode recommendation. A plain array
in `config.modes` is still a full replacement (back-compat).

==============================================================================
8. MULTI-TASK SUBAGENTS                            *agent_core-multitask*

agent_core.multitask exposes run_agent_tool(), a write-capable subagent tool
for the owned runtime's tool registry. Emit multiple run_agent tool calls in one
message to run subagents concurrently. The tool accepts prompt (required), an
optional tools allowlist, an optional worktree flag that isolates the subagent
in a detached git worktree, and optional profile/model overrides that run the
subagent under a different named profile or model.

Worktrees are SEQUENTIAL-ONLY (the process cwd is shared): a second worktree run
is rejected while one is active. Profile/model overrides are per-session, so
overridden subagents fan out in parallel.

==============================================================================
9. MODE RECOMMENDATION                            *agent_core-recommend*

agent_core listens for the owned AgentInputSubmitted event and classifies each
prompt against the active mode's realm. If the prompt is out of scope (e.g.
"implement this feature" in ask, "fix this bug" in plan), it suggests switching
to the best-fit mode with a Switch/Ignore prompt.

Classification is hybrid: a fast offline keyword heuristic runs first; for
low-confidence prompts a one-shot LLM classification goes through the owned
provider transport, degrading gracefully to the heuristic on failure or timeout.

Modes carry two realm-hint fields in lua/agent_core/modes.lua: keywords
(weighted phrases; { "phrase", 2 } for stronger signals) and when_to_use (the
one-line reason shown in the prompt). The active mode's read_only flag also
boosts full-write modes when an imperative edit verb is detected.

Config lives under |agent_core-config| recommend = { ... }.

==============================================================================
10. AGENT AUTOSWITCH                              *agent_core-autoswitch*

agent_core also classifies each AgentInputSubmitted prompt against profile
strengths (keywords) and, when a different provider/model is a better fit,
offers a Switch/Ignore prompt. Profiles expose keywords (weighted phrases),
when_to_use (the reason shown), and autoswitch = false to exclude a profile
from routing (the local Ollama model is excluded).

Routing is hybrid: a fast offline keyword heuristic runs first, and a one-shot
LLM classification goes through the owned provider transport for low-confidence
prompts, degrading gracefully to the heuristic on failure.

Default strengths: DeepSeek (cloud) for general coding, Gemini for fast /
long-context / multimodal work, Claude for architecture / security / reasoning,
and a custom agent (e.g. the "GPU Ollama (qwen2.5-coder)" example shipped in
the user's <data>/agent_core/profiles.json, private-remote) for private /
offline / sensitive work.
Config lives under |agent_core-config| autoswitch = { ... }.

When the mode recommender and the autoswitch both fire on the same prompt,
agent_core.coordinator merges them into a single prompt with Switch both /
Switch mode only / Switch profile only / Ignore options.

==============================================================================
11. MCP INDEXING                                    *agent_core-mcp*

ripvec (semantic + BM25 + LSP search) is natively multi-root: its retrieval
tools accept a `root` parameter and lazily index that root. semnav (LSP
semantic graph) is strictly per-root, so agent_core registers one semnav-<slug>
MCP server per registered project that supports a semnav language
(Go/Rust/JS/Python), and runs a one-time `semnav index` when a graph DB is
missing. mcphub starts servers lazily (auto_toggle_mcp_servers), so N projects
do not spawn N daemons at startup; tracked daemons are stopped on VimLeavePre.

agent_core manages the global ~/.config/mcphub/servers.json, preserving
non-agent_core servers and recomputing only its own ripvec + semnav-* keys.

==============================================================================
12. WORKSPACE REGISTRY                            *agent_core-workspace*

The workspace registry persists multiple project roots so the agent can search
and reason across several repos. Entries are { path, name, summary, added_at }
stored in <data>/agent_core/workspace.json — structural metadata only, never
file contents or secrets.

Use :AgentWorkspaceAdd (current dir or a path), :AgentWorkspaceScan (git repos
under a parent folder), :AgentWorkspaceRemove, :AgentWorkspaceList, and
:AgentWorkspaceSwitch (cd into a project). The registry is injected into the
system prompt via |agent_core.get_workspace_prompt()|: a compact index of name,
path, and one-line summary per project. The active project keeps its full
brief; other projects are searched on demand via MCP (see |agent_core-mcp|).

Config lives under |agent_core-config| workspace = { ... }.

==============================================================================
13. WEB ACCESS                                      *agent_core-web*

agent_core.web exposes two read-only custom tools (wired into the owned
runtime's tool registry):

  web_fetch    Retrieve an http(s) URL and return readable plain text.
  web_search   Best-effort DuckDuckGo search returning titles, URLs, snippets.

Both run through `curl` with a user agent and a hard timeout, are read-only,
and are safe to auto-approve in full modes.

==============================================================================
14. GITHUB CONTEXT                                 *agent_core-github*

agent_core.github exposes a single `github` custom tool that wraps the GitHub
CLI (`gh`), plus `git` for commits/push. Actions:

  pr <number>            Pull a PR and its comments.
  issue <number>         Pull an issue and its comments.
  search <query>         Search prs/issues/code/repos (search_type field).
  create_pr <title>      Open a PR (body/base/head optional).
  commit <message>       git add -A + git commit.
  comment <number>       Comment on a PR (body required).
  push                   Push the current branch.

Read actions build an allowlisted `gh` subcommand (never an arbitrary shell
string). Write actions (create_pr/commit/push) are explicit `gh`/`git`
subcommands built from discrete arguments and are added to destructive_tools,
so read-only modes cannot invoke them. Requires `gh` on PATH and an
authenticated remote.

==============================================================================
15. NOTEPADS                                       *agent_core-notepad*

agent_core.notepad stores user-authored markdown notes under
<data>/agent_core/notepads/ and injects a compact title index via
|agent_core.get_notepad_prompt()|. The model reads a note's full content on
demand, so notes stay opt-in. Commands: |:AgentNotepad|, |:AgentNotepadNew|,
|:AgentNotepadEdit|, |:AgentNotepadDelete|. Only titles are ever auto-injected,
never full note content.

==============================================================================
16. RULES AUTO-INJECTION                          *agent_core-rules*

agent_core.rules aggregates the instruction files agent-style editors honor —
AGENTS.md / CLAUDE.md at the project root plus
.agent_core/rules/*.mdc|md (project) and <data>/agent_core/rules/*.mdc|md (user) — into one
bounded system-prompt block via |agent_core.get_rules_prompt()|, mirroring the
rules hierarchy (project rules first, then user rules).

Frontmatter is parsed: `description` and `globs` are surfaced in the injected
heading, and `alwaysApply: false` (or a non-`always` type) injects only the
rule's metadata as an on-demand note. With `rules.auto_attach_globs` on
(default), a rule that carries `globs` is injected in full only when the active
file matches one of them (`**/*.go`, `*.py`, ...); otherwise it is listed
on-demand. The `read_rule` tool (in |agent_core.get_custom_tools()|) reads any
rule's full body by label or file basename on demand.

==============================================================================
17. BEST-OF-N                                      *agent_core-bestofn*

agent_core.bestofn fans one prompt out to N configured profiles and shows their
outputs side-by-side in a read-only scratch buffer. Each profile is queried
concurrently with its own provider/model/API key through the owned provider
transport.
|:AgentBestOfN| (or <leader>ab) runs the comparison. By default it runs every
profile with autoswitch ~= false; override with `bestofn.profiles`. Set
`bestofn.timeout_ms` to bound each model.

==============================================================================
18. PLAN MODE                                       *agent_core-plan*

Plan mode produces a reviewable plan you approve before any code
changes. agent_core.plan mirrors this with two custom tools and two commands:

  create_plan(title, content)  Write a Markdown plan to config.plan.dir
                               (default .agent_core/plans/) as <slug>-<date>.md.
  update_plan(content[, path]) Rewrite the current plan in place.

The plan persona instructs the model to research, ask clarifying questions and
wait, then write the plan (exact file paths, an ordered "- [ ]" TODO checklist,
and trade-offs) and stop — no code edits. |:AgentPlanBuild| switches to agent
mode and submits the plan as the prompt ("Build"); |:AgentPlanBuildNew|
opens a fresh agent session (best-effort "Build in New Agent"). Plan mode is
read-only for repo code but allow_tools whitelists its own plan/todo tools.

Every plan now carries a status in its YAML frontmatter, and the plan manager
tracks both drafted plans and undrafted ideas so nothing gets lost across
chats.

Status lifecycle (stored as `status:` in each plan's frontmatter; a plan
without frontmatter reads as `draft`):

  draft → in_progress → completed → abandoned → draft

|:AgentPlanBuild| marks the built plan `in_progress`. |:AgentPlans|
(`<leader>aq`) opens a scratch-buffer manager with three sections — Unfinished
plans (draft + in_progress), Completed / abandoned, and Ideas. Keymaps:
`<CR>` open a plan (or promote an idea), `s` cycle a plan's status, `n` add an
idea, `p` promote an idea into a real plan file, `x` delete an idea, `q`/`<Esc>`
close. |:AgentPlanIdea| `[title]` adds an idea to the backlog directly.

Ideas live in a project-scoped JSON backlog (`.agent_core/plan_ideas.json`, or
`config.plan.ideas_file`), each as `{ id, title, notes, created }`; promoting
one writes a real plan via `write_plan` and removes it from the backlog.

Reminders (popup + badge) ~

When the current project has unfinished plans or undrafted ideas, agent_core
surfaces them two ways (both project-scoped, gated by `config.plan.remind`):

  startup_popup  `vim.notify` once per session on startup when items remain.
  indicator      a persistent, collapsible floating badge showing the counts.

The badge shows `agent_core · N unfinished plan(s) · M idea(s)`. Keymaps:
`<CR>`/`e` expand it into the full |:AgentPlans| manager, `q`/`<Esc>` dismiss it
for the session (|:AgentPlansToggle| or `<leader>aQ` re-opens it). Dismissal
resets on directory change or when the outstanding count goes 0 → non-zero.

Both surfaces auto-refresh in real time: every plan/idea mutation
(`write_plan`, `set_status`, `add_idea`, `remove_idea`, `promote_idea`, and the
`update_plan` tool) emits a `User AgentPlanChanged` autocmd that the badge
listens for, so drafting a plan or capturing an idea immediately updates (or
re-surfaces) the badge — no reload or `:cd` required.

`config.plan.remind`:

  {
    enabled = true,       -- master switch (startup popup + indicator)
    startup_popup = true, -- vim.notify once per session
    indicator = true,     -- persistent, collapsible badge
  }

==============================================================================
19. DEBUG MODE                                      *agent_core-debug*

Debug mode instruments the failing path, asks you to reproduce, reads
the resulting logs, fixes the root cause, then removes the scaffolding.
agent_core.debug provides the same loop with three custom tools:

  add_debug_instrumentation(file, text)
      Record the exact snippet the model just inserted, into
      <data>/agent_core/debug/<root>.json (data dir only, safe in all modes).
  request_reproduction(steps)
      Signal instrumentation is complete; the model then stops so you can
      reproduce and paste the output.
  remove_debug_instrumentation
      Delete every recorded snippet by exact text match (idempotent; the real
      fix is a separate edit, so cleanup never deletes it).

|:AgentDebugCleanup| runs the same cleanup manually. The debug persona walks the
6-step loop: (1) generate multiple hypotheses, (2) add instrumentation, (3)
request reproduction and wait, (4) analyze the returned output, (5) make a
focused fix, (6) verify and remove instrumentation. Runtime evidence is captured
via an optional config.debug.log_file / log_cmd (read back by the model), so no
long-running daemon is needed.

==============================================================================
20. CHECKPOINTS                                   *agent_core-checkpoint*

Agent mode supports checkpoints so a bad change can be reverted.
agent_core.checkpoint mirrors this without commits or stash:

  checkpoint tool / :AgentCheckpoint [label]
      Snapshot the working tree to <data>/agent_core/checkpoints/<label>.patch
      via `git diff --binary` (tracked changes only).
  rollback tool / :AgentRollback [label]
      Reverse the recorded patch with `git apply -R` (a picker lists snapshots
      when no label is given).

The agent persona reminds the model to checkpoint before large or risky
changes.

PER-TURN KEEP / DISCARD                  *agent_core-session-edits*

Complementing whole-tree checkpoints, agent_core.session_edits journals every
file mutation the active chat makes (write_to_file and str_replace) so edits can
be reverted at per-turn granularity, matching Cursor's Keep / Undo All:

  :AgentKeep               Lock in the current turn's edits (advance the
                           discard baseline). Files are already persisted, so
                           this is pure bookkeeping. Keymap <leader>aK.

  :AgentDiscard            Revert every un-kept turn's edits since the last
                           keep, in LIFO order. Files the agent created are
                           deleted; overwritten files are restored to their
                           prior bytes. Keymap <leader>aX.

Journals live at <data>/agent_core/session_edits/<session_id>.json (configurable
via config.session_edits.dir). Scope: only write_to_file and str_replace are
journaled in v1; bash shell mutations are still covered by the whole-tree
|:AgentRollback| checkpoint.

COMMAND + KEYMAP CHEAT SHEET                  *agent_core-cheatsheet*

agent_core.cheatsheet renders a grouped, floating reference of every `Agent*`
command and the key currently bound to it. The key column is introspected from
live global normal-mode keymap state at render time (via |vim.keymap.get()|), so
it always reflects the user's actual mappings rather than a hardcoded table.

  :AgentCheatsheet / <leader>a?
      Open the panel. Press `r` to re-render and re-read current keymaps, or
      `q` / `<Esc>` to close.

Commands are organized into curated sections (Chat & sessions, Profiles &
models, Modes & routing, Plans & ideas, Checkpoints & undo, Debug, Completion &
edits, Workspace & indexing, Registry & endpoints, Notepad, Automation, Skills
& commands, Tools) with a catch-all "Other" bucket so no command is ever
dropped. Unmapped commands are shown with an em dash (—).

==============================================================================
21. TAB AUTOCOMPLETE                             *agent_core-completion*

agent_core.completion closes the biggest remaining gap: Tab autocomplete
that predicts code. Two pieces:

  FIM insert      A blink.cmp source (require("agent_core.completion").blink_source(),
                  or module = "agent_core.completion" in blink's providers) that
                  streams a fill-in-the-middle completion from a local Ollama FIM
                  model (default qwen2.5-coder:7b-instruct) via POST /api/generate.
                  Cloud providers fall back to a completion prompt through
                  |agent_core.run()|.

                  NOTE: Ollama FIM requires an INSERT template ({{ .Suffix }}).
                  qwen2.5-coder / codellama / starcoder2 / codegemma /
                  deepseek-coder-v2 ship one; base deepseek-coder:6.7b / 1.3b
                  do NOT (Ollama rejects `suffix` with "does not support insert").
                  Build a `deepseek-coder-fim:*` alias with a modelfile (see the
                  README) to use a local DeepSeek model. On CPU-only hosts a
                  1.5b-class model is the right latency choice (~30 tok/s vs ~7
                  tok/s for 6.7b).

  Predictive edit |:AgentPredictEdit| rewrites a window around the caret,
                  grounded in surrounding code, vim.diagnostic.get() diagnostics,
                  and a buffer-local recent-edit log. It checkpoints first, shows
                  the change in a diff split, and applies it — |:AgentRollback|
                  undoes it.

  Jump-in-file   |:AgentNextLocation| asks the edit model for the next edit
                 location (a line number), clamps it to the buffer, and moves
                 the caret there — the "jump" gesture after accepting a
                 predictive edit.

Wire the source in blink.cmp's sources.providers and set config.completion.* to
pick the FIM model and endpoint.

22. LOCAL BUGBOT                                  *agent_core-bugbot*

agent_core.bugbot runs a local bug-review agent. |:AgentBugbot| captures the
working-tree diff (git diff HEAD) or a branch diff (git diff <base>...HEAD), fans
out to parallel review workers over diff chunks, and presents a severity-ranked
report (file/line, explanation, suggestion). With --autofix it applies the fixes
in an isolated new-branch git worktree, commits, pushes, and opens a PR via
`gh pr create`. Write paths are destructive and gated on --autofix. The `bugbot`
custom tool exposes the same review/autofix to the model.

agent_core.memory is agent-written, persistent memory — distinct from user-authored

24. HEADLESS RUNNER                               *agent_core-runner*

agent_core.runner runs a single agent headlessly and returns its final answer,
so agents are scriptable from git hooks, cron, or `nvim --headless`:

  require("agent_core").run("Fix the failing test", { mode = "debug" }, cb)

|agent_core.run()| resolves a profile, assembles the same system prompt the
interactive agent gets, and streams through the owned provider transport.
|:AgentRun| runs it interactively. This is the local analog of a headless SDK
runtime and Automations (which run on a cloud VM).

25. LIFECYCLE HOOKS                                *agent_core-hooks*

agent_core.hooks emits lifecycle events so users can extend agent_core with
their own Lua. Set callbacks under config.hooks (or listen for the matching
User autocmd):

  before_prompt  AgentHookBeforePrompt  a prompt is submitted (agent input)
  after_prompt   AgentHookAfterPrompt   right after submission
  before_tool    AgentHookBeforeTool    an agent_core custom tool runs
  after_tool     AgentHookAfterTool     an agent_core custom tool completes
  on_run_end     AgentHookRunEnd        a headless run completes

before/after_tool wrap agent_core custom tools only (wired through

26. PLATFORM SUPPORT                            *agent_core-platform*

agent_core is platform-agnostic and runs identically on Linux, macOS, and
Windows. A shared agent_core.platform helper centralizes the OS-specific
decisions:

  is_windows()    true on native Windows Neovim
  is_abs(path)    POSIX `/`, home `~`, drive `C:\`/`C:/`, and UNC `\\server`
  resolve_bin(n)  absolute paths pass through; bare names use vim.fn.exepath
  join(...)       join parts with forward slashes (portable on Windows)
  shell_and()     `&&` on POSIX, `;` on Windows (brief build/test commands)
  os_hint()       model-facing shell/path instructions (wired via
                  |agent_core.get_os_hint()| into the system prompt)

Binary resolution (curl, gh, semnav, ripvec-mcp) and the indexer's non-git
file walk are portable; the mcphub servers.json path tracks mcphub's own
resolved config.

External CLIs used at runtime (resolved on PATH per-OS): git, curl (web +
FIM completion), gh (GitHub tool), and semnav / ripvec-mcp (MCP indexing).

==============================================================================
27. REAL DEBUGGER (DAP BRIDGE)                     *agent_core-dap*

agent_core.dap adds a genuine interactive debugger the AI drives end-to-end,
giving the model real debugger event parity without any upstream fork. It is a
thin, adapter-agnostic controller over nvim-dap: it speaks only nvim-dap's
generic API, so every DAP adapter (codelldb, delve, debugpy, js-debug,
java-debug, netcoredbg, one-small-step-for-vimkind, ...) is supported with no
per-language code here.

The model drives the debugger through custom tools (all wired via
|agent_core.get_custom_tools()|):

  debug_list_adapters    List adapters + launch configs for the buffer.
  debug_start            Launch by config name or inline config; optional
                         breakpoints; blocks until the first stop.
  debug_set_breakpoint   Set a breakpoint at file:line (condition / logpoint /
                         hit count).
  debug_clear_breakpoint Clear one breakpoint or all.
  debug_continue         Resume; blocks until the next stop or termination.
  debug_step_over        Step over; block until the stop and return state.
  debug_step_into        Step into; block until the stop and return state.
  debug_step_out         Step out; block until the stop and return state.
  debug_pause            Interrupt a running process.
  debug_get_state        Non-blocking snapshot of the last stop + console output.
  debug_get_variables    Expand a variablesReference into child variables.
  debug_evaluate         Evaluate an expression in the paused frame.
  debug_stop             Terminate the session.
  debug_restart          Restart; block until the first stop.

The blocking tools (debug_start, debug_continue, debug_step_*, debug_restart)
issue the DAP command and HOLD their on_complete until the debugger actually
stops, then return the full paused state (source line, stack frames, scopes,
locals, and captured console output). Because the owned runtime feeds a
tool_result back into the conversation, this is event-identical to an injected
"paused" message — no rewrite required. The tools stay out of destructive_tools
so the debug loop runs uninterrupted in full modes.

The debug mode persona (|agent_core-modes|) now PREFERS the real debugger when
an adapter is available for the language (discovered via debug_list_adapters):
set breakpoints at hypotheses, launch, step, inspect, evaluate, find the root
cause, and apply a minimal fix. When no adapter fits (hard-to-attach or non-DAP
scenarios like timing/network/async races), it falls back to the instrumentation
loop in |agent_core-debug|.

nvim-dap is SOFT-REQUIRED: without it (or a debug adapter) the tools return a
clear error and the instrumentation loop remains the fallback. Installing
nvim-dap and the per-language adapters is user-side; agent_core supplies only
the AI-facing controller.

Adapter install (user config):

  Go        nvim-dap-go + delve
  Python    nvim-dap-python + debugpy
  JS/Node   nvim-dap + mason (vscode-js-debug)
  Rust/C/C++ nvim-dap + mason (codelldb)
  Java      nvim-jdtls + java-debug
  C#/.NET   nvim-dap + mason (netcoredbg)
  Lua       one-small-step-for-vimkind

Define dap.configurations per filetype in your config (read by
debug_list_adapters and debug_start); e.g. for Go:

  local dap = require("dap")
  dap.configurations.go = {
    { type = "go", name = "Debug file", request = "launch",
      program = "${file}" },
  }

Commands: |:AgentDebugStart| (<leader>aD), |:AgentDebugContinue|,
|:AgentDebugStepOver|, |:AgentDebugStepInto|, |:AgentDebugStepOut|,
|:AgentDebugStop|, |:AgentDebugStatus|. Config lives under |agent_core-config|
dap = { ... } (timeout_ms, max_frames, max_variables, max_output_chars).

28. MODEL REGISTRY + POLICY                        *agent_core-policy*

agent_core.registry is the single source of truth for every model backend nvim
can reach. Each entry carries the role(s) it serves (primary for chat,
completion/edit for Tab and edits, classifier for routing), a trust tier
(local, private-remote, or third-party-cloud), and value tags (cost, latency,
fim, reasoning, quality_tier, plus numeric cost_in_per_1m / cost_out_per_1m /
quality_score / context_window from the catalog). Ollama models are
auto-discovered from EVERY configured endpoint (`registry.ollama_endpoints`
plus the loopback default; /api/tags), each stamped with its endpoint and trust
tier (loopback = local, non-loopback = private-remote); remote backends are also
declared via config.completion.backends or |:AgentRegistryAdd|. Each entry gets
an `enabled` flag (persisted setup.json override wins over env/key presence).
Exposed API: list(), for_role(role), by_trust(...), find(name), add(entry),
remove(name), parse_ollama_tags(body, endpoint, trust), normalize(entry),
entry_enabled(entry).

agent_core.policy turns that registry into a selection policy from three
ORTHOGONAL knobs (no flat presets):

  model_policy  balanced (default = all three) | good | fast | cheap, or any
                1-3 of them (e.g. { "good", "fast" })   -- the iron triangle
  trust_scope   any (default) | private | local            -- data sovereignty
  caution       act_first (default) | ask_first            -- mutation behavior

Named ALIASES compose all three at once (M.ALIASES): privacy = balanced +
private + act_first; cautious = cheap + local + ask_first; question_first =
balanced + any + ask_first; quality = good + any + act_first; speed = fast +
any + act_first; cost_first = cheap + any + act_first.

Each axis enforces a hard bound where it applies: good requires a quality floor
(quality >= 0.5), fast rejects high-latency models (latency ceiling), and cheap
rejects the expensive tier (cost ceiling). Two-axis combos intersect these
bounds and sum the two scores.

Everything else is DERIVED from the knobs so they cannot drift (with
model_policy now an axis selection, each cheap/good behavior fires whenever that
axis is present, including in a 2-axis combo; all three axes collapse to
balanced):
  - classifier (autoswitch/recommend LLM fallback): disabled when trust_scope
    excludes cloud or under cheap (classification would send prompt content out).
  - destructive_tools: expanded (file mutations, run_agent, create_plan, ...)
    only under ask_first -- see effective_destructive_tools().
  - max_tokens: trimmed under cheap (see completion.effective_max_tokens()).
  - mode bias: ask_first biases plan/ask; good biases plan.

apply() returns the policy object consumed by autoswitch (filter + re-rank),
recommend (mode bias), completion (backend selection), and modes
(effective_destructive_tools). Selection order is strict: role capability ->
policy filter/weights -> content rank -> health, so a policy can pick DIFFERENT
models per role (e.g. local scope: local chat model + local FIM model +
classifier disabled).

Completion backends + health router (|agent_core-completion|):

config.completion.backends (or auto-discovered Ollama models) is the FIM pool.
The policy sets the allowed trust tier (hard, from trust_scope) and the
preferred backend (weight, from model_policy); a health router walks candidates
in policy order, picks the first reachable endpoint (/api/tags, short timeout),
caches for 30s, and FAILS OVER to local when the preferred backend is down.
On switch it warms the model (keep-alive) so the first keystroke is not cold.

Commands: |:AgentPolicy| (<leader>ay), |:AgentRegistryList|, |:AgentRegistryAdd|.
Config lives under |agent_core-config| registry = { ... } and policy = { ... }.

29. MODEL CATALOG + SETUP WIZARD                    *agent_core-setup*

agent_core.catalog is the single source of truth for every model backend nvim
can reach: identity (provider/model/name/roles/trust), the metadata that cannot
be derived at runtime (per-token cost, benchmark quality_score, authoritative
fim / insert_template / reasoning / vision flags, context_window, latency_hint),
and — for entries that double as chat agents — the persona + routing fields
(description, system_prompt, autoswitch, keywords, when_to_use). These ship as
a bundled, versioned snapshot (lua/agent_core/catalog_snapshot.lua) and can be
refreshed from a pinned URL via |:AgentCatalogUpdate| (config.catalog.url).
agent_core.profiles projects the entries that carry a system_prompt into the
profile list used by autoswitch/runner/registry; entries without one stay
catalog-only. The policy scoring (|agent_core-policy|) uses the numeric fields
directly — cheap enforces a cost ceiling and weights -cost, good weights
quality_score, fast weights latency_hint + measured latency — with a
coarse-string fallback for unknown user models.

SECURITY: a fetched catalog is untrusted remote input, so only non-security
numeric fields are accepted (cost_*, context_window, quality_score, fim,
insert_template, reasoning, latency_hint, model list). It can never set
api_key_name, endpoint, trust, name, roles, description, system_prompt,
autoswitch, keywords, or when_to_use — a malicious/compromised catalog cannot
make the wizard read an unexpected env var, point at a hostile endpoint, or
inject routing/persona metadata (those ship only in the bundled snapshot).

The registry AUGMENTS every declared chat profile with the catalog's numeric
fields and additionally SURFACES catalog-only chat models (e.g. GPT-4o mini,
Claude Haiku) whose key is present in the environment — the deterministic answer
to "what other LLMs should I include".

|:AgentSetup| (<leader>aS) is the plug-and-play entry point:
  - detect() reports which providers have an env key or a stored key, and the
    full Ollama endpoint set (local + declared remote).
  - form_model() renders one row per chat-capable model (toggle, key presence,
    derived cost/quality/trust tags), greyed when disabled.
  - save() stores keys via agent_core.keys, persists the enabled-provider set to
    <data>/agent_core/setup.json, records remote Ollama endpoints, then runs
    finish_setup(): a default-profile picker (falling back to the first keyed
    cloud model, else local), a default-mode picker, and a guided policy
    selector (model policy / trust scope / caution), ending with one summary.
  - bootstrap_suggest() makes ONE LLM call over catalog tags only (never key
    values), returning { model_policy, trust_scope, caution, default_profile },
    presented as Apply / Apply with edits / Skip and live-applied via
    agent_core.policy + agent_core.profiles. With no AI it degrades to
    balanced / any / act_first + the first keyed profile. This is OPT-IN:
    setup.bootstrap defaults to false, and the deterministic finish sequence
    always runs regardless.

The persisted setup.json `enabled` map WINS over live env detection, so a key
added/removed from the environment after setup does not silently flip a profile;
re-running |:AgentSetup| is the reconcile path. On a fresh install with no
setup.json and no active profile, setup.auto_prompt offers the wizard on first
load (headless-safe). Remote Ollama boxes (GPU hosts over VPN) are added via
|:AgentEndpointAdd|, |:AgentRegistryAdd|, or registry.ollama_endpoints; their
models are stamped private-remote and auto-discover in the wizard.

Every item |:AgentSetup| configures has a standalone command, so nothing is
locked behind the wizard: |:AgentKey| (keys), |:AgentProfileEnable| /
|:AgentProfileDisable| (enabled set), |:AgentEndpointAdd| /
|:AgentEndpointRemove| / |:AgentEndpointList| (endpoints), |:AgentSwitch|
(profile), |:AgentMode| (mode), |:AgentModel| (pooled active model), and
|:AgentPolicy| (policy). |:AgentManager| is
the single interactive panel that edits all of these in one place.

30. AGENT SKILLS                                    *agent_core-skills*

agent_core.skills discovers reusable, self-contained procedures stored as
SKILL.md files. Each skill has a small YAML frontmatter (name, description,
argument-hint, user-invocable) plus a markdown body. Skills live under
.agent_core/skills/<name>/SKILL.md (project) and
<data>/agent_core/skills/<name>/SKILL.md (user).

Only metadata is auto-injected: |agent_core.get_skills_prompt()| emits a compact
index (name + description + argument hint) bounded by skills.prompt_max_chars.
The model reads a skill's full body on demand with the `read_skill` tool (also
returned by |agent_core.get_custom_tools()|), so skill bodies never bloat the
prompt. |:AgentSkills| lists every discovered skill with its scope and path.

Skills marked `user-invocable: true` are also user-runnable: |:AgentSkill|
(<leader>at) opens a picker of invocable skills, collects the argument hint, and
shows the invoked body (with `{{args}}` / `{arg}` placeholders substituted) for
review. The `run_skill` tool lets the model do the same.

Config lives under |agent_core-config| skills = { ... }.

31. IMPORT FROM ANOTHER IDE                        *agent_core-import*

agent_core.import migrates an existing third-party IDE setup into agent_core's
neutral directories. It is the ONLY module that names source-IDE on-disk paths,
and it is single-source (one IDE per run) and non-destructive (existing files
are never overwritten).

Cursor source:
  .cursor/rules/*.mdc|md (project + user)  -> .agent_core/rules (project) /

32. AUTO CONTEXT ATTACH                           *agent_core-context*

agent_core.context builds a bounded `## Current context` system-prompt block
from the editor's live state — the active buffer window around the caret, the
current visual selection, and the LSP diagnostics for the buffer — so the agent
sees your current file, selection, and linter errors without any manual
@-mention. |agent_core.get_context_prompt()| is the export the owned runtime

|context.max_lines| / |context.max_chars|,

33. ASK THE USER                                      *agent_core-ask*

agent_core.ask exposes an `ask_user` tool (in |agent_core.get_custom_tools()|)
so an agent can ask a clarifying question mid-task and wait for the answer
instead of guessing. The question is surfaced through `vim.ui.input` and the
answer is returned to the model; in a headless session (no UI) it fails fast
with an actionable error so the agent can proceed with a documented assumption
rather than hanging. Enabled by default (|agent_core-config| ask.enabled).

34. SESSION HISTORY                                *agent_core-history*

agent_core.history lists, resumes, renames, forks, and rewinds prior agent chat
sessions. |:AgentHistory| (<leader>aH) opens a picker over prior sessions and
resumes the selected one into the Agents Window. |:AgentRename| (<leader>ar)
renames the current session; |:AgentFork| (<leader>aF) copies it into a new
chat; |:AgentRewind| (<leader>aU) jumps it back to an earlier message.
|:AgentSessionBind| (<leader>ah) binds the current session to a profile, so
resuming that chat restores its model. `M.list(dir)` / `M.load(dir, id)` /
`M.load_into_sidebar(id)` / `M.rename_session(id, title)` /
`M.fork_session(id, title)` / `M.rewind_session(id, index)` /
`M.bind_profile(id, profile)` are the programmatic form. The history store is
the owned runtime history directory (<data>/agent_core/history), overridable
via |agent_core-config| history.dir. Each session record carries its own title,
profile, provider, and model, so there are no sticky side-stores.

NOTE (per-session models): provider/model are per-session fields, so multiple
open chats can each run a different model simultaneously. |:AgentSessionBind|
additionally pins a profile to a chat so resuming restores that model.

37. COMMAND PALETTE                               *agent_core-commands*

agent_core.commands discovers curated shell commands stored as one file per
command: `.agent_core/commands/<name>.cmd.md` (project, committed) and
`<data>/agent_core/commands/<name>.cmd.md` (user-global). Each file has a small
YAML frontmatter (name, description, trust, argv, args, required) plus an
optional markdown body: >

  ---
  name: run-tests
  description: Run the test suite
  trust: safe
  argv:
    - pytest
    - -q
    - "{{pattern}}"
  args:
    - pattern
  required:
    - pattern
  ---
<

The model invokes commands through a single constrained `run_command` tool (in
|agent_core.get_custom_tools()|): it emits a short command ID plus typed `args`
instead of generating a full free-form command string. The harness builds the
`argv` array deterministically (never shell-interpolated), so commands are
cheap, unambiguous, and injection-safe.

`trust: safe` (default) commands are enumerated in the `run_command` tool and
auto-approved. `trust: dangerous` commands are excluded from the tool and left
to the approval-gated `bash` breakout. Only metadata is auto-injected:
|agent_core.get_commands_prompt()| emits a compact index (name + description +
args), bounded by `commands.prompt_max_chars`. |:AgentCommands| lists every
command; |:AgentCommand| picks and runs one interactively.

Config lives under |agent_core-config| commands = { ... }.

38. IMAGE INPUT / VISION                            *agent_core-vision*

agent_core.image exposes a `read_image` tool (in |agent_core.get_custom_tools()|)
that reads an image file (relative to the project root or absolute), base64-
encodes it, and sends it to a vision-capable profile for a description or a
specific question. Resolve the profile explicitly with
|agent_core-config| image.vision_profile, override just the model with
image.vision_model, or let agent_core auto-pick the first enabled registry entry
tagged `vision` (catalog models such as GPT-4o, Claude, Gemini, and Ollama
vision models such as `llava` / `moondream`). The active profile is only used as
a last resort when it is itself vision-capable — a text-only model is never
silently sent an image; `read_image` fails with a clear error instead. Images
larger than image.max_image_bytes are refused.

agent_core.runner.llm_curl() accepts an optional `images` list
({ data, media_type }) and builds the multimodal array-form content the owned
runtime expects, so image + text prompts work through agent_core's own paths
(headless runner, automations, and custom tools). For interactive chat, image
input is handled by the owned clipboard bridge: install img-clip.nvim
(paste/drag-drop); the Agents Window panes use the `markdown` filetype, so
render-markdown.nvim renders pasted images inline.

The owned runtime guards interactive pastes: when the active model cannot see
images (e.g. DeepSeek), the paste is handled per image.paste_guard — "block"
(default, refuse the paste), "warn" (notify but still paste), "auto_switch"
(switch to the vision profile first), or false (disable). This closes the gap
left by validating image capability only at the API layer.

39. DIFF UX                                        *agent_core-diff*

agent_core.diff is the shared diff presenter every agent edit path funnels
through — predictive edit, inline edit, coordinated edits, and bugbot autofix —
so they all get the same review UX. It renders old/new lines as per-hunk chunks
and lets you accept or reject each hunk before applying. The working tree is
checkpointed first (|agent_core-config| diff.auto_checkpoint), so
|:AgentRollback| undoes an applied edit (and a cancelled coordinated edit rolls
back automatically).

Commands: |:AgentDiffApply| (<leader>aa) applies the accepted hunks,
|:AgentDiffAccept| (<leader>aY) accepts the hunk under the caret, and
|:AgentDiffReject| (<leader>aN) rejects it. In the diff buffer, `a` toggles the
hunk under the caret and `q` cancels. In a headless session (no UI) the
presenter auto-accepts every hunk so scripted callers still get a deterministic
apply.

40. COORDINATED EDITS                              *agent_core-edits*

agent_core.edits predicts and applies a coordinated change across several files
at once — the multi-file "Tab v2" gesture. |:AgentCoordinatedEdit| (<leader>aE)
starts from the symbol under the caret, gathers cross-file context (the current
file plus up to |agent_core-config| edits.context_files ripgrep-matched files,
bounded by edits.max_files / edits.max_chars), and asks an edit-capable profile
to return a structured JSON edit set: >

  [{ "path": "relative/path", "find": "exact text", "replace": "replacement" }]
<

Every path is validated to stay inside the repo root (absolute paths and `..`
traversal are rejected) and each `find` must match a literal block in its file.
The harness checkpoints, applies each edit, and presents a combined diff with
accept (keep) / cancel (|:AgentRollback|). Configure the edit model with
edits.edit_profile / edits.edit_model; edits.enabled disables the command.

41. CHAT WORKSPACE                           *agent_core-chat-workspace*

The default chat surface is a Cursor-style workspace opened with |:AgentChat|
(<leader>a<Space>): a chat list (left), a message view (right), and a multi-line
composer (bottom).

  Chat list     The |:AgentChat| sidebar. "Open" shows live sessions, "History"
                shows persisted chats (newest-first). <CR> focuses an open chat
                or resumes a history entry; r renames, d deletes, / filters,
                q closes.
  Message view  Reuses the Agents Window pane buffer, so streaming, tool
                blocks, and the model indicator behave as before. <Tab> /
                <S-Tab> cycle open chats; q closes the workspace.
  Composer      A markdown scratch buffer. Enter sends; Shift+Enter inserts a
                newline; <C-n> starts a new chat; <C-m> picks the model;
                <C-d> picks the mode; <C-s> stops the running turn;
                <C-x><C-o> opens the @-mention / slash-command menu; q closes.

The composer sends through the owned runtime's submit path, so `/plan`,
`/mode`, `/profile`, `/workflow`, and `/agent` slash commands and `@file`,
`@git`, `@codebase`, etc. mentions all expand exactly as in a plain submit.
Picking a model in the composer applies it to the current session and persists
it on the session record (per-session model memory), so resuming that chat
restores its model. <C-s> cancels the in-flight provider stream; the cancelled
turn is never persisted, and the pane shows "cancelled".

Tool results render as collapsible `## Tool · <name>` blocks (marker folding),
so long call outputs fold away. The plain Agents Window grid remains available
for side-by-side multi-chat via |agent_core-history| resume / the owned UI.
